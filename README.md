# MouthOfGod_System


AI生成により、不自然です。


> 触感デバイスが口の中に食感を伝えます。プレイヤーはその食感から食べ物・生物を特定します。その食べ物・生物を生み出して、世界（ミニチュアの村）を再構築するゲームです。
> *This game is ...*（TLDR の英文は応募時に確定します）

IVRC に出展した作品を、GDC 向けに再構成するプロジェクトです。IVRC 版との最大の違いは 2 つです。1 つは **「ゲームとして成立させること（ゲーム性・チュートリアル設計）」** です。もう 1 つは **神様コンセプトの前面化** です。

## プロジェクト管理

やることはすべて **Issue** にし、**マイルストーン**に入れています。マイルストーンは、ゴール（応募動画 → 応募）に向かう**日付つきの区切り**です。期限の近い区切りから順に終わらせます。Issue 同士の順番は、**Relationships → Blocked by** で表します。これは各 Issue の右側にあり、先に終わっている必要がある Issue を示します。

**普段の流れ**
1. 下の「今の区切り」の「すぐ着手できる」から選びます。
2. 何日かかけて進めるなら、その Issue の **Assignee に自分を入れる**ようにします。すると「着手中」に出るので、2 人が同じものを始めなくなります。その日のうちに終わるときや、誰がやるか合意が取れているときは付けなくて構いません（[CONTRIBUTING「作業の進め方」](CONTRIBUTING.md#作業の進め方)）。
3. PR で Issue を閉じます。図と活動記録は自動で更新されます。
4. 週に 1 回（例: 月曜）、ロードマップを見て今週やるものを決めます。⚠ が出ていたら、削るか後ろへ回すかを決めます。
5. ミーティングで話すことには、Issue にラベルを付けます。見てほしいなら **`mtg-share`**、その場で決めたいなら **`mtg-decide`** を使います。同じことを **議題 Issue**（「次の MTG の議題と議事録」）にも書きます。MTG のあとは、議事録を議題 Issue に書きます。それからラベルを外し、議題 Issue を閉じます（[CONTRIBUTING「作業の進め方」](CONTRIBUTING.md#作業の進め方)）。

新しい Issue を作ったら、マイルストーン（どの区切りか）と Blocked by を設定します。

## 1. コンセプト：あなたは神様
<img width="888" height="507" alt="image" src="https://github.com/user-attachments/assets/2de52110-8915-4ed4-b515-ca72c7abd2cd" />

プレイヤーは、村で信仰されている神様です。

1. 神様は村から奉納された食べ物（お供え物）を食べて暮らしています。
2. その食感を覚えています。
3. ある日、村が食料難に陥ります（木にリンゴがならない、川に魚が現れない）。
4. 神様は雲や霞を食べます。そして、**お供え物と同じ食感のものを口から生み出して**、村を助けます。

> 「なぜこの操作をするのか」「なぜこの目的を達成したいのか」を、世界観が説明します。これが神様コンセプトの役割です。

## 2. ゲームの骨子

| 項目 | 内容 |
|---|---|
| 目的 | 適切な食べ物を、適切な場所に届ける |
| 操作 | フォーク型のデバイスで雲を刺す。先を口に含んで噛みます。食感は時間で変化します。狙った食感になった瞬間に決定すると、それが生み出されます |
| チャレンジ | 口の中の感覚だけで「今のは牛だ」と見分ける |
| 成功 | 適切な食べ物を適切な場所に届けられた |
| 失敗 | 時間内に届けられなかった |
| スコア（仮） | 住民の満足度が高いほどハイスコア |
| 手応え | 自分が生み出したもので村が豊かになっていく |

### 体験のイメージ
- 目の前に、山・海・草原・村のフィールドを持つミニチュアの村があります。
- 最初にお供え物を食べ、「食べ物と食感の対応」を覚えます。
- フォーク型のデバイスで、周りに浮かぶ雲（霞）を刺します。その一部を口に含んで噛むと、食感が時間ごとに切り替わります。
- 出せるのは、はっきりした食べ物の食感（リンゴの食感など）ではありません。**見分けられる数種類の食感**を出します。それぞれが 1 つの食べ物・生物に対応します。どれに対応させるかは #54 で決めます。
- 欲しい食感の瞬間にボタンで決定します。すると、その食べ物・生物が口から生み出されます。
- それを必要な場所に届ける（例: リンゴ→村の木、魚→海）。何をどこに届けるかは #54 で決めます。
- プレイヤーはミニチュアの周りを移動して場所を選びます。位置はコントローラーで取得します。

### IVRC 版からの変更点
| | IVRC | GDC |
|---|---|---|
| 復元される対象 | 食品だけ | 食品だけでなくてもよい（牛・魚などの生物も） |
| コンセプト | 神様コンセプトは裏設定 | **神様コンセプトを前面に** |
| ユーザーの移動 | 移動しない | 移動してもらう（見栄えのため） |

## 3. 体験フロー

**体験はすべて英語で行います**。語り・画面の文・スタッフの説明も英語にします。この節は日本語の下書きです。英語の文は [シナリオブック](docs/scenario-book.md)（仮）にあります。

1 人あたり約 8 分かかります（Quest をつけている間は約 6 分）。数字はすべて仮で、試遊しながら変えます。詳しい案と経緯は [#38 のコメント](https://github.com/Fialuxe/MouthOfGod_System/issues/38#issuecomment-6083490067) にあります。

  M --> E[エンディング]
  E --> R[外す・消毒<br/>次の人]

| 場面 | 時間（仮） | どこで |
|---|---|---|
| 受付・説明・Quest とデバイスをつける | 1 分 | ブース（スタッフ） |
| プロローグ | 45 秒 | 座っても立ってもよい |
| 台の前へ | 15 秒 | スタッフが案内 |

GDC には 1 人あたりの時間の決まりはありません。目安は、出展者の助言（デモは 10 分くらいに収める）とします。混んだときのために、本編の制限時間は設定（データ）で変えられるようにします。

### プロローグ（仮）
**お供え物は食べず、見せるだけ**にします。食感は、台の前へ移動したあとのチュートリアルで初めて体験します。座って見ても、立って見ても構いません。

伝えること（#21）:
- あなたは神です
- あなたは口からものうみだせます
- あなたはこの村の人々から信仰されていました
- ある日、村に飢饉が起こり、お供えものがなくなり、村の人達が困っています
- あなたの出番です
- さぁ、助けましょう的な

見せ方は 2 案あります（#38）。

### チュートリアル
最終的にやらせたいことは、**場所に応じた食べ物を口の中から生成し、ミニチュアを豊かにする**ことです。ここから逆算して、段階的に教えます。簡単なことから本筋へ近づけます。

1. お供え物を食べて、食べ物と食感の対応を覚える
2. デバイスの使い方を理解する（フォークで雲を刺して口に含む／噛むと食感が切り替わる／ボタンで決定）
3. 噛んで決定すると物が出てくることを知る
4. 出てきた物で何をしてほしいかを知る（必要な場所に届ける）
5. 木のフィールドで実際にやってみる（例：リンゴを木へ）
6. 木以外のフィールドでもできることを体験する（例：魚を川へ）

各ステップのゴールは「**どうやるか**を理解させること」です。目的が分かりやすい状況を用意して、やりたいと思わせます。

6 ステップを、チュートリアル 1〜4 の Issue に次のように割り当てます。

| チュートリアル | 扱うステップ |
|---|---|
| 1（#12）デバイスの使い方 | 2 |
| 2（#13）噛むと物が生まれる | 1、3。お供え物はプロローグで見せるだけなので、食感はここで初めて体験します |
| 3（#14）食感で物が変わる・要求を知る | 4 |
| 4（#15）届ける | 5、6 |

### メイン体験（本編）
**2 分（仮）のあいだ、村のあちこちで「これが欲しい」が出ます。プレイヤーは歩いて行き、噛んで生み出して届けます。** 届けた分だけ村が豊かになります。**ここが「一番楽しいところ」です。**

- **フィールド**: 山・海・草原・村の 4 つです（雪は山に含めます）。定義は [docs/fields.md](docs/fields.md) にあります。どのフィールドが何を欲しがるかは #54 の対応表で決めます。
- **欲しい物の出し方**: 村人の頭の上に吹き出しで出します。同時に、そのフィールドを光らせます。最初の 30 秒は 1 つずつ出します。そのあとは同時に最大 2 つ出し、プレイヤーがどちらから行くかを選びます。
- **間違えたとき**: 物が霞になって消え、村人が首を振ります。欲しい物は残ります。罰は付けず、失うのは時間だけにします。
- **ゲーム性**:
  - 吹き出しに待ち時間のゲージ（20 秒）を付けます。間に合わないと村人ががっかりし、その分の満足度は入りません。
  - 食感は時間で切り替わります。そのため、欲しい食感の瞬間に決定すること自体が腕前になります。
  - 間違えずに続けて届けると、ご褒美が大きくなります（下の「満足度とご褒美」）。
  - 難しさは、待ち時間の長さと同時に出る数で調整します。試遊でクリア率を見て決めます（#16）。
- **終わり**: 残り 10 秒でカウントダウンします。時間切れで止め、届けている途中の物は消します。

### 満足度とご褒美
「やった！」を、すぐに・何度も・少しずつ大きく感じさせます。そうして、もう 1 回届けたくなるようにします。

| ねらい | どう見せるか |
|---|---|
| すぐ返す | 届けた瞬間（0.5 秒以内）に、音・光・村人の歓声・「+満足度」が出ます |
| 積み上がりが見える | 届けた物は村に残り、村が目に見えて育ちます |
| 続けるほど大きく | 連続で当てると、音の高さが上がり、光が大きくなります。外すと元に戻ります |
| ときどき大当たり | まれに「金のリンゴ」「村人が踊る」など、予想していないご褒美が出ます |
| 惜しいを伝える | 外したとき、正解の食感が近かったら「惜しい！」と出します |
| 最後にためて見せる | エンディングで星を 1 つずつ発表します |
| 人と比べられる（案） | ブースのモニターに「今日の神様」上位を出します |

満足度の計算は単純にします。届けた数 × 連続ボーナスで出します（#78）。細かい計算より、届けた瞬間の手応えを優先します。

### 体験終了（エンディング）
- プロローグと同じ語りで閉じます（例: 「そなたのおかげで、村に恵みが戻った…」）。
- VR 酔いを避けるため、カメラは動かしません。プレイヤーの周りの村が、届けた分だけ豊かになっているのを見せます。
- 星を 1 つずつ、間をためて出します（3 段階）。そのあと、豊かになった村全体と、笑顔の村人の数を見せます。満足度の数字は小さく添えます。
- 最後に「体験は終わりです。デバイスを口から外して、そのままお待ちください」を出します。そのあと自動で待機画面に戻ります。

### 途中でやめた・止まったとき
**キーボードも Inspector も使いません**。できるだけ自動にします。残りは Quest のコントローラーで操作します。

- **自動**:
  - 待機画面で Quest をかぶると、プロローグが始まります。
  - 途中で外すと一時停止します。つけ直すと続きます。
  - 外したまま 30 秒たつか、エンディングが終わると、待機画面に戻ります。このとき、村・欲しい物・満足度を初期状態（飢饉）に戻します。AprilTag の位置合わせは残します。
- **スタッフ**: 左のコントローラーを持ちます。誤操作を防ぐため、操作はすべて長押しにします。押している間は、視界の端にゲージを出します。

| 操作（左のコントローラー） | すること |
|---|---|
| X を 2 秒長押し | 今の場面を飛ばして次へ |
| Y を 2 秒長押し | どこからでも待機画面に戻す |
| X と Y を同時に 3 秒長押し | デバイスが動かないとき、Mock 入力に切り替えます。スティックで食感を切り替え、トリガーで決定します |

- 体験者の手は、フォークを持つだけにします。**届け先は、体験者が立っている場所**（ミニチュアの周りの位置）で決まります。口から生まれた物は、目の前のフィールドに落ちます。位置とフォークの取り方は #40・#62 で決めます。

## 5. 開発の進め方（概要）

- リポジトリ: https://github.com/Fialuxe/MouthOfGod_System
- Git のブランチ運用と Scene Fusion を使います。詳細は [CONTRIBUTING.md](./CONTRIBUTING.md) を参照してください。
- ブランチの使い分け: 機能は `feature/`、バグは `fix/`、シーン制作は `scene/` を使います。
- 実行用の共有シーンは `Assets/Scenes/Main.unity` の 1 つだけにします。動作確認用シーンは `Assets/Scenes/Sandbox/` に自分専用のものを作ります。
- コードの型の名前とデータの置き場所（`Assets/Resources/Data/`）は、[CONTRIBUTING.md「型の名前とデータの置き場所」](./CONTRIBUTING.md#型の名前とデータの置き場所) にあります。

### 動画審査
- 見られるのは**冒頭だけ**と考えます。最初にゲーム内容を分かりやすく伝え、補足は後半に回します。
- 「何をするゲームか」「チャレンジ内容と成功/失敗」「面白さ」を伝えます。新規性があると有利になります。
- 最も楽しいところだけを映せば十分です。5 分より短くて構いません。

| 構成 | 内容 |
|---|---|
| TLDR | どんなゲームかを一目で。文字＋プレイ画面。`This game is ...` |
| Concept | 世界観、やってほしいこと、避けたいこと。「あなたは神です」、なぜそれをやるのか |
| Play View | メイン体験の最も楽しい部分 |
| Appendix | デバイスの仕組みなどの補足 |
