# clarify-reply

> この仕組みを直す前に、[仕組みの前提](../../../docs/automation-premise.md) を読む（補助線であって決まりではない。人の負荷を増やさない）。

人と Claude が、GitHub のコメントで返事をし合うための手順。人が「わからない」と書いたとき、**元の文は直さず**、言い直した返信を、同じ Issue・PR に足す。元の文を直すと、人が読んだ文と変わってしまい、返信の流れが追えなくなる。確認は取らず、最後まで実行する。

## 手順

### 1. 「わからない」を探す
- 直近 12 時間のコメントを集める: `gh api "repos/{owner}/{repo}/issues/comments?since=<12 時間前の ISO 時刻>" --paginate`（Issue と PR の両方が入る）。
- 次の両方に当てはまるものを選ぶ。
  1. **人のコメント**である。次のどれかを含むものは、Claude のコメントなので除く: `<!-- claude`、`Generated by [Claude Code]`、`Generated with [Claude Code]`。
  2. **Claude が書いた文への返事**である。その Issue・PR の本文が Claude の下書き（本文の先頭が「この Issue は Claude が下書きしました」、またはラベル `claude-proposal`）か、そのコメントより前に Claude のコメント（目印つき）がある。
- そのうえで、コメントの中に次の合図がある。行ごとに見る（1 つのコメントの中に、答えと「わからない」が混ざることがある）。
  - 「わからない」「分からん」「意味が」「どういう」「何を言っているのか」「前提が」「ピンとこない」「初見では」
- 同じコメントの id で、`<!-- claude-clarify:<コメントの id> -->` を含む Claude のコメントがすでにあれば、飛ばす。
- 1 回の実行で書く返信は、**3 件まで**。

### 2. 何が分からなかったかを特定する
- 「わからない」と書かれた行と、その前後を読み、**どの質問・どの文**が通じなかったかを特定する。
- 元の Claude の文から、その部分を取り出す。表の番号で指されていたら、表の行まで取り出す。
- リポジトリの文書とコード（`docs/`、`Assets/Scripts/`）と、その Issue・PR の本文・コメントで、**書かれていなかった前提**（言葉の意味、数の根拠、食い違い）を確かめる。確かめられないものは、「未確認です」と書く。推測で埋めない。

### 3. 言い直しを書く
次の形で、下書きを一時ファイルに書く。

```
失礼しました。「<通じなかった文や項目を、短く引用>」は、<何が足りなかったか>を書かずに進めていました。意図していたのは、次のことです。

<前提を補って言い直した文。元の質問が選択肢つきなら、選択肢も書き直す>

<元の質問の中に、確かめて見つけた間違いがあれば、ここで直したと書く>

<今も答えられる状態か（期限・答え方）を 1 行>
<!-- claude-clarify:<わからないと書いたコメントの id> -->
```

- 「失礼しました」は最初に 1 回だけ。長い謝罪や、元の文の言い訳を書かない。
- 言い直しは、[書き方のルール](../ask-decision/SKILL.md)（項目名の下に字下げして書く、名前は初めて出るその場で説明する）に従う。
- 人の名前に `@` を付けない。
- 人の答えがすでにコメントされているなら、**その答えを書き換えない**。言い直しによって答えが変わるかを、1 行で聞く形にする。

### 4. 読ませて、直す
[cold-read](../cold-read/SKILL.md) の手順で、下書きを読ませる。「分からない所はありません」になるまで直す（最大 3 回）。

### 5. 投稿する
- `gh issue comment <番号> --body-file <一時ファイル>`（PR のコメントも同じ）。元のコメントへの返信として、本文の先頭に、元のコメントの URL を 1 行で添える。
- 元の Claude のコメントや本文は、**編集しない**。

### 6. 記録する
- 通じなかった型を、`docs/question-lessons.md` に足す PR を作る（ブランチ名 `claude/question-lessons`、すでに open の同名 PR があればそこに足す。マージは人）。足し方は `issue-hygiene` の「通じなかった質問を、記録に足す」と同じ。

## 報告
返信した件ごとに 1 行（番号・何が通じなかったか）。何も見つからなければ「該当なし」。公開リポジトリなので、トークンや個人情報を書かない。
