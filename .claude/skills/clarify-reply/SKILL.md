# clarify-reply

> この仕組みを直す前に、[仕組みの前提](../../../docs/automation-premise.md) を読む（補助線であって決まりではない。人の負荷を増やさない）。

人と Claude が、GitHub のコメントで返事をし合うための手順。人が「わからない」と書いたとき、**元の文は直さず**、言い直した返信を、同じ Issue・PR に足す。元の文を直すと、人が読んだ文と変わってしまい、返信の流れが追えなくなる。確認は取らず、最後まで実行する。

## 入力
- `comment=<コメントの URL>`（GitHub Actions の「Claude mention」が、コメントに `@claude` があったときに渡す）: そのコメント 1 件だけを扱う。手順 1 は飛ばして、手順 2 に進む。
- 入力が無いとき（定期実行・手で呼ぶとき）: 手順 1 で探す。

## `@claude` の範囲
- 扱うのは、次の 2 種類です。どちらも、読むだけで答えられるものに限る。
  - **言い直し**: 「どういうこと？」「意味が分からない」のように、Claude の文を分かるようにしてほしい依頼。手順 2 以降に進む。
  - **状況更新・調べもの**: 「状況更新して」「いまどうなってる？」「この Issue の担当は？」のように、リポジトリと GitHub に書かれた事実を集めて答える依頼。下の「状況更新・調べもの」に進む。
- それ以外の依頼（実装してほしい、Issue を閉じてほしい、ラベルや担当を変えてほしい、など書き込みや変更が要るもの）には、1 行だけ返す: 「言い直しと状況の確認以外の依頼には、まだ答えられません。」（目印は同じ）。
- 状況更新と調べものでも、Issue・PR・ファイルは**変えない**。答えのコメントを 1 件足すだけ。
- `@claude` を付けたコメントがどの文への返事か分からないとき（Claude の文が見当たらないとき）は、「どの文のことか分かりませんでした。引用して教えてください。」と 1 行返す。
- owner・member・collaborator 以外の人のコメントには、何もしない。理由は、公開リポジトリで他の人の指示では動かないためです。入力がある場合は、Actions が先に確かめています。

## 状況更新・調べもの

`@claude` のコメントが、言い直しではなく状況の確認のとき、次の手順で 1 件だけ返す。

1. **対象を決める。** コメントが付いた Issue・PR の本文と、全コメントを読む。コメントが別の Issue や PR の番号を指していたら、それも読む。
2. **事実を集める。** 本文の表やリストに並んだ Issue・PR の番号ごとに、状態・担当・最後の更新を `gh issue view N --json state,stateReason,assignees,updatedAt,comments`、`gh pr list --state all --search "#N in:body" --json number,title,state` で確かめる。リポジトリの文書やコードは、答えに要るものだけ読む。
3. **答えを書く。** 最初の 1 文に、全体の状況を書く。続けて、本文に並んだ項目ごとに「いまの状態・担当・つながる PR」を 1 行ずつ書く。確かめられなかったものは「未確認です」と書き、推測で埋めない。
4. **人に求めることを増やさない。** 遅れや未着手を並べて詰めない。事実を短く書き、決める人が要るものだけ、末尾に「決めることは、〇〇です」と 1 行で添える。
5. [cold-read](../cold-read/SKILL.md) で読ませて直し（最大 3 回）、`gh issue comment <番号> --body-file <一時ファイル>` で投稿する。本文の先頭に、元のコメントの URL を 1 行で添え、最後の行に `<!-- claude-status:<元のコメントの id> -->` を付ける。同じ id の目印がすでにあれば、返信しない。
6. 手順 6（記録）は不要です。報告には、返信した Issue の番号と、「状況更新」と書く。

## 手順（言い直し）

### 1. 「わからない」を探す（入力が無いとき）
- 直近 12 時間のコメントを集める: `gh api "repos/{owner}/{repo}/issues/comments?since=<12 時間前の ISO 時刻>" --paginate`（Issue と PR の両方が入る）。
- 次の両方に当てはまるものを選ぶ。
  1. **人のコメント**である。次のどれかを含むものは、Claude のコメントなので除く: `<!-- claude`、`Generated by [Claude Code]`、`Generated with [Claude Code]`。
  2. **Claude が書いた文への返事**である。次のどちらかに当たる。
     - 本文が Claude の下書きである。先頭が「この Issue は Claude が下書きしました」か、ラベル `claude-proposal` がある。
     - そのコメントより前に、目印つきの Claude のコメントがある。
- そのうえで、コメントの中に次の合図がある。行ごとに見る（1 つのコメントの中に、答えと「わからない」が混ざることがある）。`@claude` が付いたコメントは、合図が無くても対象にする。
  - 「わからない」「分からん」「意味が」「どういう」「何を言っているのか」「前提が」「ピンとこない」「初見では」
- 同じコメントの id で、`<!-- claude-clarify:<コメントの id> -->` を含む Claude のコメントがすでにあれば、飛ばす。
- 1 回の実行で書く返信は、**3 件まで**。

### 2. 何が分からなかったかを特定する
- 「わからない」と書かれた行と、その前後を読み、**どの質問・どの文**が通じなかったかを特定する。
- 元の Claude の文から、その部分を取り出す。表の番号で指されていたら、表の行まで取り出す。
- リポジトリの文書とコード（`docs/`、`Assets/Scripts/`）と、その Issue・PR の本文・コメントで、**書かれていなかった前提**（言葉の意味、数の根拠、食い違い）を確かめる。確かめられないものは、「未確認です」と書く。推測で埋めない。

### 3. 言い直しを書く
次の形で、下書きを一時ファイルに書く。

```
失礼しました。「<通じなかった文や項目を、短く引用>」は、<何が足りなかったか>を書かずに進めていました。意図していたのは、次のことです。

<前提を補って言い直した文。元の質問が選択肢つきなら、選択肢も書き直す>

<元の質問の中に、確かめて見つけた間違いがあれば、ここで直したと書く>

<今も答えられる状態か（期限・答え方）を 1 行>
<!-- claude-clarify:<わからないと書いたコメントの id> -->
```

- 「失礼しました」は最初に 1 回だけ。長い謝罪や、元の文の言い訳を書かない。
- 言い直しは、[書き方のルール](../ask-decision/SKILL.md)（項目名の下に字下げして書く、名前は初めて出るその場で説明する）に従う。
- 人の名前に `@` を付けない。
- 人の答えがすでにコメントされているなら、**その答えを書き換えない**。言い直しによって答えが変わるかを、1 行で聞く形にする。

### 4. 読ませて、直す
[cold-read](../cold-read/SKILL.md) の手順で、下書きを読ませる。「分からない所はありません」になるまで直す（最大 3 回）。

### 5. 投稿する
- `gh issue comment <番号> --body-file <一時ファイル>`（PR のコメントも同じ）。元のコメントへの返信として、本文の先頭に、元のコメントの URL を 1 行で添える。
- 元の Claude のコメントや本文は、**編集しない**。

### 6. 記録する
- 通じなかった型を、`docs/question-lessons.md` に足す PR を作る（ブランチ名 `claude/question-lessons`、すでに open の同名 PR があればそこに足す。マージは人）。足し方は `issue-hygiene` の「通じなかった質問を、記録に足す」と同じ。

## 報告
返信した件ごとに 1 行（番号・何が通じなかったか）。何も見つからなければ「該当なし」。公開リポジトリなので、トークンや個人情報を書かない。
