# cold-read

> この仕組みを直す前に、[仕組みの前提](../../../docs/automation-premise.md) を読む。

書き手には当たり前のことは、読み手には当たり前ではない。「分からない」と言われてから直すのではなく、**投稿する前に**、前提を知らない目で読ませて直す。

## 手順

1. **下書きを、一時ファイルに書く**（投稿する本文そのもの。Issue や会話の文脈は添えない）。
2. **読ませる**: `python3 .claude/skills/cold-read/cold_read.py <ファイル>`
   - `claude -p` を、指示文を短くしてツールを外して軽く起動する（サブエージェントで呼ぶより、1 回あたり約 39,000 トークン少ない）。モデルは `COLD_READ_MODEL`（既定は sonnet）。
   - 指示の本文は `.claude/agents/cold-reader.md`。コードと対象の Issue を読んでいない、チームの一員として読む。
3. **指摘を分ける**。指摘ごとに、次のどれかを決める。
   - **直す**: 説明の足りない言葉・名前、指す先が不明な所、理由のない判断、同じ言葉が二通りに使われている所。
   - **事実を確かめて直す**: 例の誤り、数が合わない所、食い違い。指摘は、本文が間違っている手がかりになる。リポジトリの文書とコードで確かめてから直す（今回の #252 では、「村に豚が届いたとき」の例が、村が豚を欲しがる事実と合っていなかった）。
   - **直さない**: 外部のファイルや Issue の中身の引用を求める指摘（番号やファイル名に、1 行の説明があれば足りる）。年の有無のような、読み取りに影響しない指摘。
   - **未整理と書く**: 確かめても分からない所（決めた人・日付・作業量など）。推測で埋めず、本文に「未確認です」「まだ決まっていません」と書く。
4. **直して、もう一度読ませる**。「分からない所はありません」になるまで繰り返す。最大 3 回。それでも残るものは、本文に「未整理」と書く。
5. **投稿する**。本文の事実（日付・番号・決まったこと）は、読ませる過程で消さない。足した日付や期限などの案は、報告で「私が足した」と伝える。

## 守ること
- 指摘を直すために、本文に**根拠のない事実を足さない**（担当者の名前、期限、決定など）。
- 人が書いたものを書き換えない。直すのは Claude が書いた下書きだけ。
- 通じなかった質問が見つかったら、`docs/question-lessons.md` に足す（`issue-hygiene` が毎週探す）。
