# mtg-agenda

次の MTG（既定: 次の金曜）の議題 Issue を 1 つ作る。確認は取らず、最後まで実行する。**人が流し見する部分は短く**（見えている部分は 40 行以内）、根拠は折りたたみに入れる。

## 手順

### 1. 日付を決める
MTG は毎週金曜。今日より後で最も近い金曜を `M/D` にする（指示があればそれに従う）。同じ日付の議題 Issue（題に `M/D MTG` を含む open な Issue）が既にあれば、**新しく作らず**、本文の Claude の部分だけを作り直す（手順 2・3 はすべて行う。題・ラベル・担当は変えない）。Claude の部分は `<!-- claude-agenda:start -->` と `<!-- claude-agenda:end -->` で囲んで書き、**その外（人が書き足した行）は残す**。目印の無い古い議題 Issue は、本文を丸ごと Claude の部分とみなす。

### 2. 材料を集める
**日付の決まり**: 「前回の MTG 以降」は、前回の MTG の日の 0:00（日本時間）から（その日を含む。前回の日付は、直近の `docs/minutes/*.md` のファイル名）。**期限との比較は、次の MTG の日**で行う（議題は MTG の日に読まれるため）。前の節にある見出しが、古い議事録に無ければ（旧名も無ければ）飛ばす。

- `mtg-share`・`mtg-decide` が付いた open の Issue（`gh issue list`）
- 前回の MTG 以降に、閉じた Issue とマージした PR（`gh issue list --state closed --search "closed:>=YYYY-MM-DD"`、`gh pr list --state merged`）。前回の日付は、直近の `docs/minutes/*.md` のファイル名
- 直近の議事録 `docs/minutes/*.md` の「アクション」（旧「次にやる人」）、「未解決・次回」（旧「確認してほしいこと」）、「Issue にしたほうがよさそうなもの」
- **アクションの Issue ごとの状況**（前回のアクションに書かれた Issue 番号それぞれについて）: `gh issue view N --json state,stateReason,closedAt,assignees,comments`（コメントは前回の MTG の日付以降のもの）と、その Issue を参照している PR（`gh pr list --state all --search "#N in:body" --json number,title,body,state` で取り、本文に `Closes`・`Fixes`・`Resolves`・`Refs` と `#N` が並んでいるものだけ。番号の文字列が一致しただけのもの（`#1880`、表の中の番号）は除く）
- マイルストーンの期限（`gh api repos/{owner}/{repo}/milestones`）。締切が 14 日以内のもの
- README「今の区切り」と、`roadmap` ラベルの Issue
- **つながっていない作業**（Claude の盲点を埋める）: 人は、作業を Issue につながずに進めることが多い（PR に `Closes`・`Refs` を書かない、サンドボックスのシーンで作る）。前回のアクションの Issue ごとに、前回の MTG 以降の PR（`gh pr list --state all --search "created:>=YYYY-MM-DD"`）とブランチ（`gh api repos/{owner}/{repo}/branches --paginate` の各ブランチに `gh api "repos/{owner}/{repo}/commits?sha=<ブランチ>&since=<前回の MTG の日>"` をかけ、コミットの `author.login`・日付・変えたパスを見る。`git branch -r` は作者と日付が分からないので使わない）から、**その Issue の担当者（GitHub の login が一致）が作ったもの**で、題・ブランチ名・変えたパスが Issue の中身（例: 草フィールド → `tomita_grass`。日本語と英語の名前の対応は `docs/mtg-context.md` の読み替え）と重なるものを探す。見つけたら ❓ の根拠にする（✅ にはしない）
- **Claude からの質問**: `docs/mtg-context.md`「Claude からの質問」の目印 `<!-- claude-question -->` を含むもの（「聞きたいこと」は共有すること、選択肢つきは決めることへ）。コメントは `gh api "repos/{owner}/{repo}/issues/comments?since=<30 日前の ISO 時刻>" --paginate`（Issue と PR の両方が入る）、PR の本文は `gh pr list --state open --json number,title,body`。**答えが済んだものは除く**: 同じ Issue・PR に、質問より後の**人のコメント**か、`<!-- claude-answer -->` を含むコメントがある。Issue・PR が閉じたものも除く。**Claude のコメントは、代表者のアカウントから投稿されるので、投稿者では人と区別できない**。`<!-- claude` で始まる目印、`Generated by [Claude Code]`・`Generated with [Claude Code]`、または「AI 生成のため」の一文を含むものを Claude のコメントとみなす
- **全体を見る（分野ごと）**: `docs/mtg-context.md`「プロジェクトの分野」の分野ごとに、次の区切り（M2・M3 など、期限の近いもの）に**要るもの**と、**追えているもの**（open の Issue・担当・最後の動き）、**見えている進み**（PR・ブランチ・コミット）を比べる。次のものを拾い、「Claude から聞きたいこと」の候補にする:
  - 要るのに、Issue が無い・担当が無い・7 日以上動きが無いもの（例: デバイスの製作とゲームとの接続に、担当も時期も無い）
  - 閉じた Issue のうち、閉じたコメントが「未決」「そのときやる」「入選後」などで、要るものがまだ残っていそうなもの（終わったこととして共有しない）
  - 担当の居ない作業が、区切りの多くを占めている分野
  GitHub に残りにくい分野（ハードウェア、ジオラマ、各自のサンドボックス）は、記録が無いことを「進んでいない」と書かない
- **議題 Issue の人のコメント**（同じ日付の議題 Issue をすでに作ってあり、更新するとき）: 人が足した話題。本文に繰り返さない

### 3. Issue を作る
- 題: `M/D MTG の議題と議事録`
- ラベル: `mtg-share`、`claude-proposal`
- 担当（Assignee）: **全員**（`gh api repos/{owner}/{repo}/assignees --jq '.[].login'` の全員。議題 Issue と議事録は、全員で見るもので、Leading・Support は置かない）
- 本文（日本語）。**人が 1 分で読める形を先に、Claude が集めた根拠は折りたたみの中に置く**（人は上から流し見し、AI は根拠を読む。両方を同じ高さに並べない）。見えている部分は **40 行以内**。Issue 番号は、**必ず題を添える**（「#111 応募動画の構成」。番号だけでは、人は中身を思い出せない）。
  本文の Claude の部分は `<!-- claude-agenda:start -->` で始め、`<!-- claude-agenda:end -->` で終える。冒頭の 1 行:
  `> Claude の下書きです。話したいことは、この下に**コメント**で書いてください（1 話題 1 コメント、形式は自由）。`
  見える部分は、**10/10 に決めた 2 つの節「共有すること」「決めること」**（#184、CONTRIBUTING「議題 Issue」）に分ける。人がコメントで書く「共有事項」「相談事項」も、この 2 つに当たる。
  1. **共有すること**（`##` 見出し）:
     - **前回のアクション**（N 件中 M 件完了）: 1 件 1 行で「結果の記号 担当 何を（#N 題）」。⚠・⏳・❓ の行は、「決めること」で扱う旨を 1 語で添える（続ける／担当を替える／やめる）
     - **見てほしいもの**: `mtg-share` の Issue と、レビュー待ちの PR を、題つきで 1 行ずつ（最大 5 件。超えた分は折りたたみへ）
     - **Claude から聞きたいこと**（`###` 見出し。最大 3 件。材料の「全体を見る」と、状況を聞く `claude-question` から。期限の近い分野を先に）: 先頭に 1 行「Claude からは見えないので教えてください。ひとことで大丈夫です。」。1 件 2 行:
       - **〇〇って、どうなってる？**（分野。関わる Issue があれば #N 題）
       - なぜ聞くか（締切・止まりそうなもの）/ Claude に見えていること（無ければ「GitHub に記録なし」）
       開いた質問にする（「〇〇でよいか？」にしない。`docs/mtg-context.md`「Claude からの質問」）。前回の議題でも聞いて、答えが無かったものは「（2 回目）」
     - **お知らせ**: あれば、流し見できる程度に（3 行以内）
  2. **決めること**（`##` 見出し。**締切の近い順**。同じ締切なら、止めている作業が多い順）:
     - **Issue**（最大 3 件）: **`mtg-decide` の Issue を先に**載せる（人が「MTG で決めたい」と付けたもの。下の候補の条件は問わない）。枠が余れば「決めることの候補」で埋める。1 件 1〜2 行: **何を決めるか**（#N 題）— なぜ今（締切、止まっている作業の数、応募につながるか）。M/D の議題を開いた人が、ここだけ読めば MTG に出られるようにする
     - **前回のアクションの ⚠・⏳・❓**: 「続ける／担当を替える／やめる」を、まとめて 1 行で
     - **Claude からの質問**（`###` 見出し。最大 5 件。材料の「Claude からの質問」のうち、選択肢つきのもの。無ければ省く）: 先頭に 1 行「MTG で『Q1 は A』のように答えるか、元のコメントに返信してください。答えが無ければ、各質問の『決めなければ』のとおりになります。」。1 件 2 行:
       - **Q1. 質問の 1 文**（#N 題 / [元のコメント](URL)）
       - A. … / B. … — 決めなければ: …（`docs/mtg-context.md`「Claude からの質問」の形から写す）
       並びは、止めている作業が多い順。2 回目以降の MTG に持ち越したものは、質問の後に「（2 回目）」。5 件を超えた分は、折りたたみの中に件数と一覧だけ
  3. **くわしく**（`<details><summary>くわしく（Claude が集めた根拠）</summary>` で折りたたむ）: 前回以降に終わったこと（Issue・PR を題つきで）、見てほしいもの、前回の議事録の「未解決・次回」で残っているもの（決める必要があるものは、候補の条件に当てはめる）、決めることの候補の詳細（下の形）、アクションの判定の根拠（どのコメント・PR を見て判定したか）
- **アクションの結果は、事実だけで判定する**:
  - ✅ 完了: Issue が `completed` で閉じている、またはそれを `Closes` する PR がマージ済み
  - ⏹ 取りやめ: Issue が `not_planned` で閉じている
  - 🔄 進行中: open で、前回の MTG 以降にコメント・PR・コミットがある
  - ⚠ 期限切れ: open で、期限（今日）を過ぎている。動きがあっても期限切れが優先
  - ⏳ 未着手: open で、期限前、動きがなく、**材料の「つながっていない作業」も見つからない**
  - ❓ 記録なし: Issue につながる記録は無いが、**つながっていない作業が見つかった**（「❓ #236 草フィールドのサンドボックス が関係ありそう」）、または Issue 番号・期限が書かれていない。推測で ✅ や ⏳ にしない。❓ の行には「PR に `Refs #N` を書くと、次から自動で分かります」と 1 回だけ添える
  並び順は ⚠ → ⏳ → ❓ → 🔄 → ✅・⏹。
- **決めることの候補**（「決めること」の元。折りたたみの中に詳しく。**クリティカルなものだけ、最大 3 件**）: 細かい決めごと（ボタンの位置、数値、言葉づかいなど）は載せない。対象は、**`mtg-decide` がまだ付いていない、open の `decision` の Issue**（作業の Issue は対象外）。そのうち、次の**どれかに当てはまるもの**だけ。
  - **止めている作業が多い**: その Issue を先に終わらせる必要がある open の作業（小ゴールは数えない。Blocked by をたどる: `gh api repos/{owner}/{repo}/issues/N/dependencies/blocking`）が **3 件以上**
  - **期限が迫っている区切りを止めている**: 期限が 14 日以内、または過ぎたマイルストーンの Issue で、止めている作業が 1 件以上
  - **前回のアクションの ⚠ 期限切れ**で、続けるかやめるかが分かれるもの
  **載せる前に、すでに整理が済んでいないか確かめる**（決まったことを、もう一度候補にしない）: その Issue の最新のコメントと、直近の議事録の「決定事項」を読み、次のものは**候補にしない**（担当に進めてもらう。「アクション」で扱う）。
  - 方針が出ていて、残りが**作業**（図を作る、試す、書く）のもの
  - 残る問いが、**担当が一人で決められる**もの（グループで決める必要がないもの）
  - 決定事項に、すでに結論が書かれているもの
  当てはまるものが無ければ、省く（無理に埋めない）。各候補は、Issue を開かなくても分かる文脈つきで、5 行以内:
  - **何を決めるか**（「〜を決める」の形。#N 題）
  - **なぜ今**: 決まらないと止まる作業を、**題つきで 2〜3 個**。止まる先が応募（10/30）につながるなら、その旨を 1 語で添える
  - **ここまでの経緯**: すでに決まっていること・出ている方針（日付つきで 1 文）と、**残る問い**（1 文）
  - **決めるためにやること**: **1〜2 個**、動詞で。Issue の「やること」の未チェック項目と「残る問い」から取る（**自分で作り足さない**）
  - **選択肢と仮の推し**（根拠がある場合だけ。無ければ「選択肢は未整理」）と、**担当案**（根拠があるときだけ）
  決めるのは人。ここに書いたものを、そのまま `mtg-decide` にはしない。
- 末尾に、CONTRIBUTING の「MTG が終わったら」の 4 手順は書かない（mtg-sync が行う）
- **人が書いたものを書き換えない。** 議題 Issue を更新するとき（同じ日付の Issue がすでにあるとき）、人が本文に書き足した行と、コメントは残す。人のコメントにすでに書かれた話題は、本文に繰り返さない（「決めること」に載せるなら、1 行でそのコメントへリンクする）
- 何も材料がない節は省く。#183 や #186 などの既存の議題 Issue は変更しない。

### 4. 報告する
作った Issue の URL を 1 行で出力する。
