# Scene Fusion

Scene Fusion 2 は、Unity のシーンを複数人でリアルタイムに同時編集する仕組みです。Git のマージとは別物なので、使うときは次の決まりを守ります。

## セットアップ（初回のみ）

Scene Fusion 2 クラウド版（v2.0.5）は、Package Manager 経由でリポジトリに組み込み済みです。clone して Unity を開けば入ります（初回はパッケージの解決に時間がかかります）。**Asset Store 版（Lite / Indie）は LAN 専用なので使いません。**

1. [console.kinematicsoup.com](https://console.kinematicsoup.com/) でアカウントを作ります。Subscription で **Scene Fusion** を選び、**Free** で登録します（これをしないと使えません）。
2. 作ったアカウントのメールアドレスを、チームの連絡手段で管理者に知らせます。管理者がプロジェクトに招待します。今は無料枠（**2 席**）なので、招待できる人数に限りがあります。席の数え方（登録人数か同時接続数か）は、まだ確かめていません（#5）。
3. 招待メールを承認します。
4. Unity で `Window > Scene Fusion` を開き、2 のアカウントでログインします。
5. セッションのメニューで、招待されたプロジェクトを選びます（初回だけ）。

- アカウントのメールアドレスは、Unity のものと同じでも別でもかまいません（連携していません）。
- Scene Fusion の設定（`Assets/KinematicSoup/SceneFusion/Editor/SceneFusionConfig.asset`）は各自のものなので、Git で共有しません（`.gitignore` 済み）。初めて開いたときに自動で作られます。セッションの設定（マテリアル・Prefab の同期）は、セッションを作った人の値が使われます。

## 席が足りない・接続できないとき

Scene Fusion が使えなくても、開発は止めません。次の順で対処します。

| 状況 | 対処 |
|---|---|
| 3 人目以降を招待できない・参加できない（Free は 2 席） | Scene Fusion を使う人を、シーン制作の担当 2 人に絞ります。ほかのメンバーは `feature/`・`fix/` とサンドボックスのシーンで作業します。それでも足りなければ有料にします。予算申請の都合で、月額ではなく**買い切り**になる見込みです。**買う前に先生に相談します** |
| 無料枠の制約（20,000 オブジェクト、テレインの編集不可）に当たる | テレインを使わない、シーンを分けてオブジェクトの数を抑える、で対処します。それでも無理なら、有料版（買い切りの見込み）を**先生に相談します** |
| 接続できない・同期が不安定・シーンファイルが壊れる | Scene Fusion をやめ、シーンごとに担当を 1 人に決めます。`scene/` ブランチは 1 人だけが編集し、シーン単位で Git に反映します |

どの対処にするかは、#5 の検証の結果で決めます。お金がかかる対処は予算申請が要るので、**必ず先生に相談してから**決めます。

## 作業の決まり

1. **シーンと Prefab のファイルを、Git でマージしません。** `.unity`・`.prefab` は YAML で、競合を解くのが難しいためです。競合したら、どちらかを採用して、もう片方は捨てます。
2. **同じシーンを触る人は、同じブランチ・同じセッションで作業します。** 全員が同じコミットの状態から始めてから、Scene Fusion に接続します。
3. **コミットと push は、ホストの 1 人だけが行います。** セッション中の変更は全員のシーンに同期されるので、何人もがコミットすると重なって競合します。
4. **Prefab・スクリプト・設定ファイルは、ふつうどおり `feature/` で作業します。** セッションとは分けて PR を出します。
5. 共有シーンは `Main` の 1 つだけです。作業の前に、チームの連絡手段で「今 `Main.unity` を触る」と知らせます。

## `scene/` ブランチでの手順

1. どのシーンを、誰と、いつ触るかを共有します（作業する人たちが分かっていれば、チャットで言わなくてもかまいません）。同じシーンを別のブランチで同時に触りません。
2. ホストの 1 人が、`main` から `scene/<シーン名>-<内容>` を作って push します。
3. 参加する人は `git fetch && git switch scene/...` で同じコミットの状態にしてから、Unity を開きます。
4. ホストがセッションを始め、参加する人が接続します。
5. 区切りごとに、ホストがシーンを保存し、コミットして push します。ほかの人は Git を操作しません。
6. セッションが終わったら、ホストが PR を作って `main` にマージします。参加した人は `git switch main && git pull` で追いつきます。
7. シーンに新しいスクリプトや Prefab が要るときは、その場で作りません。Scene Fusion が同期するのはシーンの上の物だけで、スクリプトなどは各自の手元にある必要があるためです。先に `feature/` で作って push し、全員が取り込んでから部品を付けます。

1 人だけでシーンを触るときも、`scene/` ブランチを切って、同じ手順（ホスト＝自分）で進めます。

> **未確認のこと**: 「ホストだけがコミットする」運用は、Scene Fusion が各自のシーンファイルをどう保存するかで変わります。最初のセッションで、次の 2 つを確かめ、結果に合わせてこの文書を直します。(a) 参加した人のシーンファイルに差分が出るか。(b) ホストの保存だけで、全員の変更が入るか。
