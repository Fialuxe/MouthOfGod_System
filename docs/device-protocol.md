# 実機のデバイスとの約束（Arduino と Unity）

触感デバイスは、Arduino がモーターを動かして、先端の内容量（%）を変えます。Unity は、食感ごとに決めた内容量を、Arduino へ指令します。

この文書は、Arduino のスケッチ（`Arduino/MouthOfGodDevice/MouthOfGodDevice.ino`）と、Unity の部品（`Assets/Scripts/Device/` の `DeviceActuator`）の約束です。この約束が守られていれば、どちらか片方を直しても、もう片方はそのまま動きます。

もとは、旧プロジェクト MealBeBack のスケッチです。通信の形は、同じにしてあります。

## 役割

| 役割 | 担当 |
|---|---|
| 噛む | 体験者の左手を握る動き（手の追跡）。デバイスは、噛んだことを検知できません |
| 食感を作る | Arduino。Unity の指令どおりに、内容量を動かします |
| 決定する | ハードウェアの確定ボタン。ボタンが付くまでは、これまでどおり、左手のつまみなどで決定します |

噛む・決定する操作は、体験者のリグが持つデバイス（いまは `MockDevice`）が受け持ちます。実機がつながっていなくても、これまでどおり動きます。

## 通信の形

- USB のシリアル通信です。速さは 9600 bps です。
- 1 行が 1 つのメッセージです。行の終わりは `\n` です。`\r` は、あっても読み飛ばします。
- 知らない行と、壊れた行は、読み捨てます。Unity と Arduino のどちらも同じです。そのため、メッセージの種類を、あとから足せます。

### Unity から Arduino へ

| 行 | 意味 |
|---|---|
| `(f,80)` | 内容量を 80 % まで**増やします**。すでに 80 % 以上なら、何もしません |
| `(s,20)` | 内容量を 20 % まで**減らします**。すでに 20 % 以下なら、何もしません |
| `(c,60)` | モーターを回さずに、いまの量を 60 % と覚え直します。実物の量が、Arduino の記録とずれたときに使います |
| `(i,0)` | すぐ止めます。値は読みません |

値は、0〜100 の整数です。範囲の外の `f`・`s`・`c` は、無視します。

### Arduino から Unity へ

| 行 | 意味 |
|---|---|
| `(0,100)` | 止まっていて、いまの内容量が 100 % です。50 ミリ秒ごとに送ります |
| `(1,100)` | 動いています。動いている間は、内容量が、動き出す前の値のままです |
| `(k,1)` | 確定ボタンを押しました。押した瞬間に 1 回だけ送ります。押し続けても、1 回です |
| `(h,MOG1)` | 「ここに実機がいる」という合図です。起動した直後と、そのあと 1 秒ごとに送ります。`MOG` は Mouth Of God で、`1` は約束の版です |

### 実機の見つけ方

COM ポートの名前は、決めません。実機が合図 `(h,MOG1)` を出し、Unity がそれを拾ったポートを、実機として使います。

1. Unity は、PC の COM ポートを順に開きます。前につながったポートを、先に試します。
2. 1 つのポートで、合図が届くのを、最大 4.5 秒待ちます。Arduino は、ポートを開くと再起動するので、数秒かかります。
3. 合図が届いたポートを、実機として使います。届かなければ、閉じて、次のポートを試します。
4. 全部試してもなければ、1 秒待って、また最初から試します。
5. つながったあと、有効な行が 2 秒途切れたら、切れたと見なして、探し直します。

合図の `MOG1` と違う値（別の版）の行は、読み捨てます。そのため、版の違うスケッチとは、つながりません。約束を変えて、古いほうとつなげたくないときは、`MOG` のあとの数字を上げます。

## ずれを防ぐ決まり

内容量は、モーターを回した時間から計算した記録です。センサーで測っているわけではありません。そのため、次の決まりを守ります。

1. **Unity は、止まっているときにだけ、指令を送ります。** 動いている間（先頭が `1`）は、送りません。動いている間に食感が変わったら、最後の 1 つだけを覚えておき、止まってから送ります。
2. Unity は、`f` か `s` を、いまの量と目標の差で選びます。Arduino は、向きが逆の指令を無視します。
3. Arduino は、動いている途中で別の指令や停止を受けたら、そこまでに動いた分を、記録に足してから、切り替えます。
4. Arduino は、起動した直後を **100 %** と覚えています。実物がそうでなければ、Unity が `(c,<実際の量>)` を送って合わせます。
5. シリアルを開くと、Arduino が再起動します。そのあと、数秒たってから、合図と状態を送り始めます。Unity は、合図が届くまで、指令を送りません。

## 食感と内容量

食感ごとの内容量は、Unity の `DeviceActuator` の **Texture Amounts** に持っています。Arduino は、食感を知りません。

いまは、仮の値です。実際の値は、食感を決める #54 で決めます。

| 食感 | 内容量 |
|---|---|
| `placeholder-a` | 100 % |
| `placeholder-b` | 80 % |
| `placeholder-c` | 60 % |
| `placeholder-d` | 40 % |
| `placeholder-e` | 20 % |
| `placeholder-f` | 0 % |

a を 100 % にしたのは、起動直後の記録（100 %）と同じにして、最初の食感で動かさずに済むようにするためです。

## 配線

| 部品 | ピン |
|---|---|
| 充填モーター（A チャンネル）の向きと有効 | 5、6 |
| 吸引モーター（B チャンネル）の向きと有効 | 9、10 |
| DRV8835 のモード | 4（LOW 固定） |
| 確定ボタン | 2（ボタンのもう片側は GND） |

- 確定ボタンは、内蔵のプルアップを使います。ボタンが付いていなくても、押したことにはなりません。ピン 2 は、仮の割り当てです。
- 押し引きが逆に組まれた個体（Arduino Micro など）は、スケッチの `REVERSE_DIRECTION` を 1 にして書き込みます。
- 1 % あたりの駆動時間（`MS_PER_PERCENT`）は、実測して直します。

## Unity 側の設定

Windows の Unity エディタで Play すると、`DeviceActuator` が自動で用意されます。シーンに置いておけば、その設定を使います。

| 項目 | 既定 | 意味 |
|---|---|---|
| Use Real Device | オン | オフにすると、通信しません。Mock だけで動きます |
| Baud Rate | 9600 | スケッチの `BAUD_RATE` と同じにします |
| Texture Amounts | 上の表 | 食感ごとの内容量です |
| Tell Device Inside On Connect | -1 | 0 以上なら、つながったときに、実際の量として伝えます |

- 自動で探すとき、COM ポートを 1 つずつ開きます。Arduino は、開くと再起動します。ほかの Arduino をつないでいる PC では、その Arduino も再起動します。そのときは、Use Real Device をオフにしてください。
- 抜けたら、通信が切れたことを Console に出して、探し直します。つなぎ直せば、続きから動きます。
- Quest 単体で動かす場合は、つながりません。エラーも出ません。Quest Link で、PC から動かします。
- シリアルの読み書きには、Windows の API を直接呼んでいます。Unity の .NET の設定は、変えなくてかまいません。

## 試し方

### Arduino だけで試す

1. Arduino IDE で、スケッチを書き込みます。
2. シリアルモニターを、9600 bps、改行コード「LF」（`\n`）で開きます。
3. `(h,MOG1)` が 1 秒ごとに、`(0,100)` のような行が 50 ミリ秒ごとに、流れてくることを確かめます。
4. `(s,50)` を送って、内容量が 50 になるまで、モーターが動くことを確かめます。動いている間は、`(1,100)` と流れます。
5. 確定ボタンを押して、`(k,1)` が 1 回出ることを確かめます。

### Unity とつないで試す

1. Arduino を USB でつなぎます。
2. Unity で Play します。Console に、`[DeviceActuator] 実機につながりました（COM3）` と出ます。
3. 左手を握ると噛み始めます。食感が切り替わるたびに、内容量が動きます。
4. 確定ボタンを押すと、Console に `[DeviceActuator] 実機の確定ボタンが押されました` と出て、決定されます。
5. 棒の先端の表示（`MockDeviceModel`）には、実機が知らせた内容量が出ます。

## 約束を変えるとき

メッセージの種類を足すのは、かまいません。読み捨てる決まりなので、古いほうは、無視するだけです。
`f`・`s`・`c`・`i` と、状態の行の意味を変えるときは、Arduino と Unity を、同じ PR で直します。
