# Claude からの質問の書き方

Claude（dev-loop・merge-check など）が、人に聞きたいことを書く形。**質問は、それが関わる Issue か PR にコメントで書く**（文脈がそこにあるので、人が答えやすい）。散らばっても拾えるように、最後の行に目印を入れる。

**まず「どうなってる？」と開いて聞く。** Claude は GitHub の外（手で作っているハードウェア、手元の Unity、Slack、口頭）が見えない。見えないものに「〇〇でよいか？」と選択肢を出すと、Claude の思い込みの中から選ばせることになる。状況を知らないうちは、開いた質問にする。選択肢つきにするのは、状況は分かっていて、決めることだけが残っているときだけ。

状況を聞く質問（「〇〇って、どうなってる？」）は、記録が無い・止まって見える・Claude からは見えない作業に使う。決めてほしい質問は、状況は分かっていて、選ぶことだけが残っているときに使う。

```
**Claude から聞きたいこと**: <開いた 1 文。「〇〇って、どうなってる？」の形>
- なぜ聞くか: <締切や、止まりそうな作業を 1 行>
- Claude に見えていること: <見た記録。無ければ「GitHub に記録なし」>

答えは、このコメントへの返信でお願いします。ひとことでよいです。
<!-- claude-question -->
```

```
**Claude からの質問**: <1 文>

- どこから
   - <どこで止まったか>
- 何をやっている時に止まったか
   - <何を作っていて、何が分からなかったか>
- 何の話か
   - <その機能が何をするものか>
- 選択肢
   - A. <案。進めた後に起きること>
   - B. <案。進めた後に起きること>
- なぜ今決めるか
   - <待っている作業>
- 決めないと困ること
   - <どの段階で何に困るか。何が絞れていないか>
- 一番良さそうな案
   - <案と理由>
- 決める人
   - <担当。決まらなければ進める案>

答えは、このコメントへの返信でお願いします。
<!-- claude-question -->
```

**読む人は、この Issue も、Claude の作業の仕組みも知らない人だと思って書く。** 次を守る（守れないなら、質問せずに、状況を聞く開いた質問にする）。
- 最初の 1 文で、「何について、何を決めるのか」が分かる。型の名前・変数名・略語は、一言の説明なしに使わない
- 「どこから」で、誰（どの自動実行）が聞いているのかを書く。人には、Claude の自動実行が複数あることが見えない
- 「決める人」を必ず書く。誰が答える質問か分からないと、全員が見て見ぬふりをする
- 「なぜ今決めるか」は、待っている Issue を題つきで書く（番号だけにしない）

「決めてほしい」質問の書き方は、スキル `ask-decision` に詳しく書いてある。

- **人の答え方は自由**（返信のコメント、Slack や口頭で話す、Issue の本文を直す、のどれでもよい。ひとことでよい）。形をそろえるのは Claude の側
- 1 つのコメントに質問は 1 つ。同じ Issue に、答えの無い同じ質問をもう一度書かない
- 答えが済んだ印: 質問より後の人のコメント、または `<!-- claude-answer -->` を含むコメント（人の答えを Claude が書き戻したもの）
- Claude のコメントは、代表者のアカウントから投稿されるので、**投稿者では人と区別できない**。`<!-- claude` で始まる目印、`Generated by [Claude Code]`・`Generated with [Claude Code]`、または「AI 生成のため」の一文を含むものを Claude のコメントとみなす。**これから Claude が書くコメントには、必ず最後の行に `<!-- claude -->` を入れる**（`<!-- claude-question -->` などの目印があるものは、それでよい）。古いコメントには目印が無いので、上の 3 つで見分ける
- 人が書くこと（形式は自由）と、Claude が書くこと（目印つきの決まった形）を分けるのは、**人は書きやすさ、Claude は拾いやすさ**を優先するため
