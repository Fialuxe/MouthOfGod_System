# 10/20 に入った機能と使い方

10/20 に、体験の流れを作る部品が 6 つ main に入りました。そのうち次の 4 つは、Core を通してつながります。

- 食べ物を生んで、前へ飛ばす部品です。
- 村人の頭の上に、吹き出しを出す部品です。
- フォークで雲を刺したかを判定する部品です。
- チュートリアルの流れを書く部品です。

明日からの機能は、この部品の上に作ります。たとえば届け先の判定、本編の進行、チュートリアルの中身です。

部品ごとに、何ができるか、どう使うか、明日どこを触るかを書きます。細かい設定は、各フォルダの README にあります。

## 全体の流れ

体験者の操作から村が戻るまでは、次の順に進みます。[未] の付いた所は、まだ作っていません。

```
デバイスで決定（MockDevice なら Enter）
  → Food: 食感から食べ物を引き、口の位置に生んで前へ飛ばす
  → [未] 届け先の判定（DeliveryZone）: どのフィールドに落ちたかを決め、Receive(食べ物) を呼ぶ
  → Village: 頼まれた物ならステップが済み、村が 1 段戻る
  → UI: 吹き出しの色を変えて消す

[未] 本編（Game）: いつ欲しい物を出すかを決め、Open() を呼ぶ
  → Village: 欲しい物を出す（Issued）
  → UI: 村人の頭の上に吹き出しを出す

Tutorial: 合図（Cue）を出し、届く・決定・刺す・口に含むを待つ
Fork: 雲を刺した・口に含んだを知らせる
```

部品どうしは、互いのコードを直接呼びません。Core にある「置き場」を通して受け取ります。置き場は、いまシーンにある部品を登録しておく場所です。たとえばフィールドは `Fields`、デバイスは `Devices`、フォークは `Forks` に登録されます。新しい機能も、Core だけを参照して作れます。

## 部品ごとの説明

### 1. 全部のフィールドを置いたシーン（`compose_fields`）

亞桃さんが、4 つのフィールドを 1 つのシーンにまとめました。巫女のモデル（`Miko-san.fbx`）も入っています。場所は `Assets/Scenes/Sandbox/compose_fields.unity` です。

明日の作業で、フィールドどうしの位置関係を見ながら試すときに使えます。共有のシーン（`Main`）は `scene/` ブランチでしか直さない決まりなので、試すときは自分のサンドボックスにコピーします。

### 2. 食べ物を生んで飛ばす（Food）

デバイスで決定すると、そのときの食感に対応する食べ物が、口の位置から前へ飛びます。食感と食べ物の対応は、`FoodTable` という表に 1 行ずつ書きます。

使い方は次のとおりです。

1. シーンの空のオブジェクトに `FoodSpawner` と `FoodTable` を付けます。
2. `FoodSpawner` の Spawn Point に、口の位置のオブジェクトを入れます。
3. `FoodTable` の Rows に、食感の ID と食べ物の Prefab を 1 行ずつ足します。デバイスなしでは、食感は `placeholder-a`・`placeholder-b`・`placeholder-c` の 3 つです。
4. Play して、Space で噛み、Enter で決定します。

食べ物の Prefab は `Assets/Resources/Prefabs/Food/` にあります。いまある食べ物は carrot・pumpkin・sheep・pig・apple・fish・cow の 7 つです。Prefab のファイル名が、そのまま食べ物の ID になります。村の欲しい物（`FieldStep` の Food）にも、同じ文字を書きます。

フィールドごとに出る食べ物を変えるには、そのフィールドの Prefab にも `FoodTable` を付けます。Field Id には、フィールドの ID を入れます。変えたい食感の行だけを書けば、残りは共通の表が使われます。

明日の作業では、次の 2 つを触ります。

- 体験者がどのフィールドの前に立っているかを判定する人は、`FoodSpawner.CurrentField` に関数を入れます。入れるまでは、いつも共通の表だけが使われます。
- 届け先を判定する人は、落ちた物に付いた `IFoodItem` から食べ物の ID を読みます。Food のコードを参照する必要はありません。

詳しくは [Assets/Scripts/Food/README.md](../Assets/Scripts/Food/README.md) にあります。

### 3. 村人の吹き出し（UI）

フィールドが欲しい物を出すと、その欲しい物で助かる村人の頭の上に吹き出しが出ます。吹き出しには食べ物のアイコンが出ます。アイコンが無い食べ物は、英語の名前が出ます。届くと緑、届かずに終わると灰色になってから消えます。

吹き出しは Play で自動的に置かれます。シーンに何かを置く必要はありません。

見た目は `Assets/Resources/RequestBubbleSettings.asset` で直します。Project でこのアセットを選ぶと、大きさ・高さ・透け方・色を Inspector で変えられます。Play 中に変えてもすぐ効き、Play を止めても値は残ります。

アイコンは `Assets/Resources/Icons/Food/` にあり、ファイル名は食べ物の ID です。新しい食べ物を足したら、メニューの **MouthOfGod > Food > Generate Icons** で、Prefab を写したアイコンを作ります。手で描いたアイコンを使うときは、同じ名前の PNG をそのフォルダに置きます。既にあるアイコンは上書きされません。

### 4. 1 つのフィールドに、欲しい物を同時に複数出す（Village・Core）

1 つのフィールドに、欲しい物を同時に 2 つまで出せるようになりました。上限は、フィールドの一番上にある `FieldStages` の **Max Open Requests** で変えられます。いまは仮に 2 です。1 つの場所にいる何人かが別々の物を欲しがるほうが、ゲームとして面白いという判断です。

欲しい物には、1 件ごとに番号が付きます。同じ物の欲しい物が 2 つ出ているときは、先に出たほうに、届いた物を当てます。吹き出しは欲しい物ごとに出て、同じ村人に 2 つ出たときは上に積みます。

Play 中に試すときは、`FieldStages` を右クリックして次のメニューを使います。

| メニュー | すること |
|---|---|
| Open Next Want | 次の欲しい物を出す。2 回押すと、2 つ出る |
| Deliver Wanted Food | 出ている欲しい物のうち、一番古いものを届けたことにする |
| Complete Next Step | 次のステップを済ませる |
| Restart | はじめに戻す |

明日の作業に関わるのは、次の 2 か所です。

- 本編を作る人の手順は、次の 3 つです。
  1. `Fields` からフィールドを受け取り、`CanOpen` で出せるかを確かめます。
  2. `Open()` で欲しい物を出します。
  3. 20 秒たっても届かなければ、`Expire(番号)` で終えます。番号は、欲しい物が出たときの知らせに入っています。
- 届け先の判定（DeliveryZone）を作る人は、食べ物が落ちたら、そのフィールドの `Receive(食べ物)` を呼びます。頼まれていない物が落ちたときも呼びます。頼まれた物かどうかは、フィールドが判断します。

山・海・草原のフィールドも、同じ部品（`FieldStages` と `FieldStep`）を付ければ、コードを書かずに同じ動きになります。作り方は [docs/requests.md](requests.md) にあります。

### 5. フォークで雲を刺す・口に含む（Fork）

フォークの先が雲に触れると「刺した」、刺したまま先を口に近づけると「口に含んだ」と判定します。チュートリアル 1 の「雲を刺す → 口に含む」を進めるための部品です。雲は体験者の前に 5 つ、半円状に浮かびます。

使い方は次のとおりです。

1. フォークの先の位置に空のオブジェクトを作り、`ForkTip` を付けます。フォークの模型とは別のオブジェクトにします。
2. `ForkTip` の Mouth に、口の位置のオブジェクト（`MouthAnchor`）を入れます。
3. メニューの **MouthOfGod > Fork > Generate Cloud Prefab** で、雲の Prefab を作ります。白い球を重ねた仮の見た目です。
4. シーンの空のオブジェクトに `CloudRing` を付けて Play します。

Quest が無くても、P で刺す、M を押している間は口に入れる、の操作で試せます。

明日の作業で触る所は、フォークの位置の取り方です。フォークの位置は、手の位置（ハンドトラッキング）と AprilTag から推定します。この推定の部品はまだ無く、人が作ります。推定の部品は、`ForkTip` のオブジェクトか、その親を動かすだけで済みます。`ForkTip` を直す必要はありません。

詳しくは [Assets/Scripts/Fork/README.md](../Assets/Scripts/Fork/README.md) にあります。

### 6. チュートリアルの流れを書く（Tutorial）

チュートリアルごとに、流れを 1 つのスクリプトに書きます。このスクリプトを「人形劇スクリプト」と呼びます。書くのは、合図を出すこと、何かを待つこと、分岐の 3 つだけです。光らせる・寄せるなどの見せ方は、合図を受けたフィールドや UI が決めます。

人形劇スクリプトは `TutorialScript` を継いで書きます。

```csharp
public sealed class T1Cloud : TutorialScript
{
    public override PhaseId Phase => new PhaseId("cloud");

    public override IEnumerator Play()
    {
        ForkWait pierce = WaitForPierce(timeoutSeconds: 10f);
        yield return pierce;                    // 刺すか、10 秒たつまで待つ
        if (pierce.TimedOut) Cue("cloud.come"); // 雲を寄せる合図（名前は仮）

        yield return WaitForMouth();            // 口に含むまで待つ
        yield return WaitForConfirm();          // デバイスで決定するまで待つ
        Memory.Set("ate-cloud");                // 次のチュートリアルが読める
    }
}
```

待てるものは 4 種類です。

| 待ち | 終わるとき |
|---|---|
| `WaitForDelivery` | 物がフィールドに届いたとき |
| `WaitForConfirm` | デバイスで決定したとき |
| `WaitForPierce` / `WaitForMouth` | フォークで雲を刺したとき / 刺したまま口に含んだとき |
| `WaitForAny` | 渡した待ちのうち、どれか 1 つが終わったとき |

どれも時間切れの秒数を付けられます。

シーンでは、空のオブジェクトに `TutorialRunner` を付け、その子に人形劇スクリプトを並べます。`TutorialRunner.Begin()` を呼ぶと、子を上から順に動かします。無効にしたスクリプトは飛ばすので、1 つのチュートリアルだけを試せます。

合図を受ける側は、`Cues.Requested` を購読します。合図の名前はフィールド名から始めます（`sea.glow` など）。

明日の作業で足すものは、次の 2 つです。

- チュートリアル 1〜4 の中身は、まだ書いていません。上の形で `T1.cs` などを足します。
- `WaitForDelivery` は、届け先の判定（DeliveryZone）が `Receive` を呼ぶまで終わりません。チュートリアル 4 の「届ける」は、届け先の判定ができてから試せます。

詳しくは [Assets/Scripts/Tutorial/README.md](../Assets/Scripts/Tutorial/README.md) にあります。

## 全部を 1 つのシーンで試す

サンドボックスのシーンに次の物を置くと、今日の部品をまとめて試せます。

1. Main Camera の子に、口の位置の空のオブジェクト `MouthAnchor` を置きます。
2. `FoodSpawner` と `FoodTable` を置き、Spawn Point に `MouthAnchor` を入れます。
3. `ForkTip` と `CloudRing` を置き、`ForkTip` の Mouth に `MouthAnchor` を入れます。
4. 村（`Village.prefab`）を置きます。
5. `TutorialRunner` とその子の人形劇スクリプトを置きます。
6. Play します。デバイス（`MockDevice`）と吹き出しは自動で用意されます。

操作は次のとおりです。

| 操作 | キー |
|---|---|
| 噛む | Space |
| 決定（食べ物が飛ぶ） | Enter |
| 雲を刺す | P |
| 口に入れる | M（押している間） |
| 欲しい物を出す・届ける | `FieldStages` の右クリックメニュー |

キーの操作は開発中の確かめ用です。展示では使いません。

## まだつながっていない所

次の部品ができると、上の流れが最初から最後までつながります。明日の作業の候補です。

| 部品 | できると動くこと |
|---|---|
| 届け先の判定（DeliveryZone） | 食べ物が村に落ちると、村が戻ります。チュートリアルの「届くのを待つ」も終わります。 |
| 本編（Game）の進行 | 本編が欲しい物を出し、吹き出しが出ます。いまは右クリックメニューでしか出ません。 |
| 体験者の前のフィールドの判定 | フィールドごとの食べ物の表が使われます。 |
| 口の位置の目印（`MouthAnchor`）を共有シーンに置く | 食べ物の出る位置と、口に含む判定の位置が決まります。 |
| 手の位置からフォークの位置を推定する部品 | Quest で雲を刺せます。 |
| チュートリアル 1〜4 の人形劇スクリプト | チュートリアルが進みます。 |

届くのを待つ処理は `WaitForDelivery` です。

今日の部品は、どれも 10/20 に Unity の Play で動くことを確かめました。Quest の実機では、まだ確かめていません。
