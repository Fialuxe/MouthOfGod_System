# Issue の扱い

Issue の書き方は、[`.claude/skills/write-issue/`](../.claude/skills/write-issue/SKILL.md) にあります。この文書には、ラベル・担当・決めることの Issue の扱いを書きます。

## Assignee

Assignee は、「しばらくこの Issue を持っている」という印です（[README「プロジェクト管理」](../README.md#プロジェクト管理)）。厳密に守らなくてかまいません。

- **付ける**: 何日かかけて進めるとき。ロードマップの「着手中」に出るので、ほかの人が同じものを始めなくなります。
- **付けなくてよい**: その日のうちに終わるとき。誰がやるか、チームで合意が取れているとき（話し合いや Slack で決まっているとき）。
- 付けないと、ロードマップの「すぐ着手できる」や、ふりかえりの「次の一手」に、その Issue が出たままになります。気になるなら付けます。
- 手を離すとき（しばらく触らない、ほかの人に渡す）は、Assignee を外します。

## 担当の役割

少人数なので、役割は 3 つだけです。担当を決めるのがいちばん重いので、Issue のコメントか Slack で話して決めます。決まらなければ、Leading は「未定」のままにします。

| 役割 | 内容 | Assignee |
|---|---|---|
| **Leading** | 進める・決める人（1 人） | 付ける |
| **Support** | Leading を助ける人（1 人。いなくてもよい） | 付ける |
| **Follower** | それ以外の全員。進み具合を見て、必要なら意見を言う | 付けない |

## ラベル

| ラベル | 意味 |
|---|---|
| `decision` | 作業ではなく、決めることが中身の Issue |
| `enhancement`・`making/hardware`・`assets`・`test`・`submission`・`logistics` | 作業の種類（`enhancement` は新機能、`making/hardware` は実物づくり）。文書を作る Issue には `documentation` も付けます |
| `optional` | やれたらやる。ロードマップの数に入りません |
| `claude-proposal` | Claude が下書きした Issue |
| `deprecated` | 前提が変わって、対応しないことにした Issue |
| `roadmap`・`activity` | ロードマップ・活動記録の Issue（自動で更新。手で付けません） |
| `hygiene` | 「Issue 整理（週次）」の Issue（自動で更新。手で付けません） |

## 決めることの Issue

決めることの Issue が、作業になっても残り続けないようにします。

- **作るとき**: テンプレート「決めること」を使い、決めたあとの行き先（残る作業を移す、実装の Issue）を最初に書きます。行き先が書けないものは、決めることではなく、作業か、まだ早い話です。
- **方針が出て、残りが作業になったら閉じます。** 残る作業は、行き先の Issue に「（#N から移した）」と付けてコメントで移します。閉じるコメントには、決まったことと移した先を書きます。
- **グループで決める必要がない問い**（担当が 1 人で決められるもの）は、決めることにしません。行き先の Issue の Leading が決めます。

ミーティングの議事録の仕組みは、10 月で終わりました。過去の議事録は [docs/minutes/](minutes/) に残っています。決めたことは、それぞれの Issue のコメントと [docs/decisions.md](decisions.md) に書きます。
