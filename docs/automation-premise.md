# 仕組みの前提（議題・議事録・Issue・自動化を直す人へ）

この文書は、議題 Issue、議事録、ラベル、Claude の自動化（`mtg-agenda`・`mtg-sync`・`issue-hygiene`・`dev-loop` など）を**直したり足したりする人と AI**が、先に読むもの。チームに向けて広く知らせるものではない。

## 前提

- **これらは、みんなが楽になるための補助線**。決まりではない。使うときもあれば、使わないときもある。
- **議題は、進めることも、進めないこともある。** 全部を消化しなくてよい。飛ばした議題は失敗ではなく、次に回るだけ。
- **カチカチに決めると、プレッシャーがかかって続かなくなる。** これは、代表者が時間とお金をかけて学んできたこと。仕組みを良くしようとして、ここを踏み外しやすい。

## 直すときに守ること

- **人に求めることを増やさない。** 人の作業は「余裕があれば」にする。必ずやってもらうのは、無いと仕組みが止まるものだけ（例: MTG の録音）。
- **足りないものは、人に書かせるより、Claude が拾う側を賢くする**（例: PR が Issue につながっていなければ、Claude が探す）。
- **責める・急かす言い方をしない。** 「期限切れ」「未着手」を並べて詰めない。事実を短く書き、「どうなってる？」と聞く。
- **数えて圧をかけない。** 消化できなかった議題、答えの無い質問、遅れたアクションは、持ち越すだけ。何回目かを強調しない。
- **足すたびに、「これで誰かの負荷が増えないか」を確かめる。** 増えるなら、やめるか、軽くする。
